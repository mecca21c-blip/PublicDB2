- CONFIRMED_REQUEST: 사용자가 명시한 요구사항.

## 감사에 의해 확인된 제약

근거: `evidence/PUBLICDB1_INVENTORY_00A.txt`, §3~6.

- 대시보드만 현재 활성 UI다.
- 기존 구현의 이번 실환경 검증은 수행되지 않았다.
- WEB_PAGE 이외 방식은 현재 collector에서 거부된다.
- Source에 부서 직접 관계가 없고 URL 전역 고유성과 단일 기관 연결이 있다.
- Excel 업로드, 실제 검토 결정, 내보내기, 소스 정리/삭제 UI는 미구현이다.
- 사람/재직 반영은 미완성이다.

## 제안 — 자동 확정하지 않음

| ID | 제안 | 확정 시점 |
|---|---|---|
| P01 | 시각적 틀은 공유하되 표/트리/비교/검토 중심으로 탭별 배치 차별화 | 해당 화면 시안 검토 |
| P02 | 수집 소스 → 연락처 DB → 검토 대기 순으로 핵심 화면 먼저 설계 | 다음 시안 순서 |
| P03 | 등록·수집·추출·검토·확정을 사용자에게 구분해 표시 | 수집/검토 명세 승인 |
| P04 | Source와 기관/부서 연결 관계를 분리해 중복/충돌 처리 | 기능/데이터 계약 승인 |
| P05 | UI만 먼저 구현해 화면 확인 후 실제 기능 연결 | 전체 UI/기능 범위 승인 후 |

## 미결정 항목

사용자에게 한 번에 전부 답하도록 요구하지 않는다.
해당 화면을 검토할 때 필요한 것만 결정한다.

- 최종 사이드바 메뉴 수, 기관/조직/업무 화면 분리 여부.
- 화면별 필수 열/필터, 기본 검색 범위, 최소 창 크기.
- 이번 버전에서 실제 지원할 수집 방법과 파일 형식.
- Excel 필수 열, 연결 중복과 충돌의 행별 처리 정책.
- 정상 확인 후 자료없음의 판정 기준과 사용자의 재분류 동작.
- 담당자/재직 정보를 어디까지 확정/편집할지.
- 검토 승인/거절/보류와 반영 이력의 상세 의미.
- 연결 해제·비활성화·물리 삭제 및 복구·이력 보존 정책.
- 내보내기 형식/대상/컬럼과 통계 범위.
- 설정 화면의 실제 항목, 기술 스택 유지/변경 여부.

## 전체 Freeze 승인 조건

- 모든 최종 메뉴에 대응 화면 시안과 기능 명세가 있다.
- 주요 팝업·오류·빈 상태·저장 실패·검토 상태가 정의되어 있다.
- 각 버튼의 실제 구현 대상과 미지원 처리가 구분되어 있다.
- 기존 기능 계승 후보, 신규 구현, 보류가 문서에 분리되어 있다.
- 이미지의 예시 문구/가짜 수치가 production 계약으로 섞이지 않는다.
- 사용자가 최종 화면·기능 범위를 승인한다.

현재 승인 결과: GLOBAL_UI_FREEZE=NO.
