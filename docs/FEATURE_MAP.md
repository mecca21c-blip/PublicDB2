## 보존할 의미

근거: 보고서 §2, §4~6.

- 발견 후보와 Master 확정 데이터는 별개다.
- 접속 성공, RAW/Observation 저장 성공, 추출 성공, Master 반영 성공은 별개다.
- 원문 증거는 RAW 파일과 DB 경로·SHA-256으로 관리한다.
- 연락처는 기관·부서·업무 문맥을 갖는다. 값만 같다는 이유로 무조건 하나로 합치지 않는다.
- UNKNOWN/ADDITIVE_ONLY coverage에서 누락 후보를 만들지 않는다.
- COMPLETE_SNAPSHOT의 missing 후보도 자동 삭제가 아니다.
- Source 삭제로 증거/이력을 연쇄 삭제하는 계약은 없다. 새 삭제 계약을 먼저 합의한다.

## 계승 전에 새로 결정해야 하는 구조

1. 한 URL과 기관·부서 연결 관계.
   기존 전역 normalized_url unique + agency_id 구조는 다중 연결 요구를 그대로 충족하지 못한다.
2. UI에서 호출할 수집 → 추출 → 검토/반영의 명시적 실행 흐름.
   현재 CLI가 따로 존재하므로 화면만 붙여서 통합 실행됐다고 간주하지 않는다.
3. API/크롤링/파일/문서의 실제 지원 범위.
   등록 메뉴 노출과 collector 지원을 구분한다.
4. 검토 결정과 Master 반영의 소유권.
   변경 감지 화면, 연락처 화면, 검토 화면이 별도 반영 로직을 갖지 않도록 설계한다.
5. 삭제와 출처 보존.
   URL 연결 해제, 수집 대상 비활성화, 물리 삭제를 구분한다.
