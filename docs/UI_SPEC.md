# PublicDB2 — 화면·동작 명세 v0.1

상태: PROPOSED / 전역 UI Freeze 전 초안.
아래는 감사 결과를 바탕으로 한 설계 제안이다. 이미 구현되었거나 사용자 승인이 끝난 사양이 아니다.

## 1. 공통 디자인 기준

시각적 기준: `design/01-dashboard-reference-v0.1.png`.
어두운 남색 사이드바, 밝은 본문, 파란 주요 버튼, 흰 카드와 표, 한국어 레이블의 방향을 유지한다.
카드·입력·버튼·표·배지의 모양은 모든 화면에서 같은 규칙을 쓴다.

이미지의 1536×1024는 원본 크기다. 앱의 고정 해상도나 최소 크기 확정값이 아니다.
긴 URL·부서명은 행 높이를 깨뜨리지 않게 처리하고 전체 값에 접근할 방법을 제공한다.
상태는 색상만으로 전달하지 않고 텍스트를 함께 표시한다.

전역 구조:
- 사이드바: 화면 이동과 현재 위치 표시.
- 헤더: 현재 화면과 그 화면에서 사용할 검색/주요 동작.
- 본문: 목록 또는 업무 화면.
- 보조 영역: 선택 항목 상세 패널이나 drawer.

모든 화면에 차트·KPI·우측 등록 폼을 반복하지 않는다.
전역 검색의 범위는 미확정이며, 화면 검색을 전역 검색처럼 보이게 하지 않는다.
알림·관리자 계정 메뉴는 동작이 확정되지 않으면 장식 버튼으로 구현하지 않는다.

최종 메뉴 개수는 기능을 누락하지 않는 범위에서 합치거나 조정할 수 있다.

| S02 | 기관 관리 | 기관 목록 + 선택 기관 상세/연결 소스 | 미시안 |
| S03 | 조직/부서 | 기관 선택 + 조직 트리 + 부서 상세 | 미시안 |

| S05 | 수집 소스 | 필터/소스 표 + 기관·부서 연결/수집 상태 상세 | 다음 우선 설계 |

| S11 | 설정 | 실제 운영 설정과 저장·오류 상태 | 범위 미확정 |

## 3. 화면별 내용

### S01 대시보드

유지할 기존 의미:
- Source 수, Source 연결 기관 수, 발견 연락정보와 Master 연락처 수.
- 전화/이메일/팩스의 발견 후보와 확정값 비교.
- 수집 방법/기관 유형별 기존 집계, 최근 수집·변경·검토 요약.

새 설계 제안:
- 요약 클릭 시 관련 목록으로 이동하면서 동일한 필터 범위를 적용한다.
- 빠른 등록은 수집 소스 화면과 같은 입력/검증 계약을 사용한다.
- 수집 성공과 연락처 확정을 한 지표로 혼합하지 않는다.

검수 포인트: 카드/사이드바/목록의 같은 집계가 서로 다른 값으로 보이지 않는가?

### S02 기관 관리

기관 검색/필터, 기관명 직접 입력, 기관 상세, 하위 조직과 연결 소스를 제공하는 화면을 제안한다.
새 기관 생성은 기존 AgencyRegistry의 명시적 등록/충돌 확인 규칙을 검토해 연결한다.
이름이 같다는 이유만으로 자동 병합하지 않는다.
기관 수정·삭제의 상세 범위는 감사로 검증되지 않았으므로 별도 합의한다.

필수 상태: 미선택, 기관 없음, 생성 입력 오류, 이름 충돌, 저장 성공/실패.

### S03 조직/부서

기관 선택 → 해당 기관 조직 트리 → 선택 부서 상세 흐름을 제안한다.
상위 부서, 관련 업무, 연결 소스/연락처를 같은 문맥에서 확인한다.
이전 UI를 그대로 복사하지 않는다. 잔존 조회 API는 필요한 응답 의미를 확인한 뒤 계승 여부를 정한다.
부서 생성·수정·이동의 구체적 편집 범위는 아직 승인되지 않았다.

필수 상태: 기관 미선택, 조직 없음, 상세 로딩/오류, 관계 충돌.

### S04 업무 관리

기관/부서별 업무 목록과 선택 업무의 설명, 연결된 연락처·공식 출처를 제안한다.
Duty 모델/승격 결과를 바탕으로 조회하되 일반 CRUD가 이미 구현됐다고 가정하지 않는다.
담당자(Person/PersonAssignment)의 직접 반영은 기존 미완성 영역이며 별도 결정한다.

필수 상태: 업무 없음, 필터 결과 없음, 관련 연락처/출처 없음.

### S05 수집 소스

소스 등록·정리·실행의 중심 화면.
상단 주요 동작: 소스 추가, Excel 업로드, 선택 대상 수집, 검토/정리.
목록 제안 열: 소스명/URL, 연결 기관·부서, 수집 방법, 형식, 지원 여부,
최근 접근/수집 결과, 추출 결과, 발견/확정 수, 최근 확인 시각.
선택 상세: 기본 정보, 기관/부서 연결 목록, 수집 정책, 최근 실행, 원문 증거.

관계와 중복:
- 사용자는 한 기관/부서에 여러 URL을 연결할 수 있어야 한다.
- 기존 Source의 전역 URL 고유성과 기관 1개 귀속을 그대로 복사하면 요구를 충족하지 못한다.
- URL 자체의 중복과 기관·부서 연결의 중복/충돌을 구분한다.
- 제안: 수집 대상 Source와 기관·부서 연결 관계를 분리해 검토한다.
- 관계 모델의 최종 구조는 미확정이다. 단순히 URL unique를 지우는 방식으로 결정하지 않는다.

상태 계약:
- 등록은 수집을 자동 시작한 것으로 표시하지 않는다.
- 접근/수집, 추출, 검토/확정을 구분한다.
- 미수집, 추출 미실행, 접근 오류, 추출 오류, 미지원, 확인 필요를 구별한다.
- '자료없음'은 정상적인 접근과 대상 범위의 유효한 추출/확인 근거가 있을 때만 분류한다.
- 단순 0건, 차단 페이지, 잘못된 파서, 미지원 형식은 자료없음의 근거가 아니다.
- 자료없음 판정 규칙과 사용자 검토 방법은 구현 전에 확정한다.

정리:
연결 해제, 소스 비활성화, 소스 물리 삭제를 동일한 동작으로 취급하지 않는다.
기존 원문/출처/이력의 보존과 삭제 영향은 확인 화면에서 분명히 제시해야 한다.
삭제 범위와 복구 정책은 아직 미확정이다.

### S06 수집 이력

날짜/기관/소스/단계/결과 필터와 실행 목록을 제안한다.
상세에는 CrawlRun, Observation, ExtractionRun의 관련 정보를 구분해 보여준다.
HTTP 성공이 추출 성공이나 Master 반영 성공으로 보이지 않아야 한다.
RAW의 경로·SHA-256 등 근거를 보존하며 원문 표시 방식은 별도 설계한다.
재실행 버튼의 범위·중복 처리·지원 조건은 기능 계약에서 확정한다.

필수 상태: 실행 이력 없음, 실행 중, 접근 실패, 원문 검증 실패, 추출 실패, 성공 0건.

### S07 연락처 DB

발견 후보와 확정 연락처를 명확히 분리하는 표 중심 화면.
제안 열: 기관, 부서, 업무, 연락처 유형, 값, 상태, 출처, 최근 관찰/확인 시각.
사람/재직 데이터는 실제 지원 범위를 확정한 뒤 표시/편집 계약을 추가한다.

선택 상세: 공식 출처, 원문 근거, 소속/업무 문맥, 변경 이력.
주요 동작 제안: 검색/필터, 상세 확인, 검토로 이동, 승인 범위에 맞는 내보내기.
같은 전화번호/이메일이 있다는 이유만으로 다른 부서의 연락처를 자동 병합하지 않는다.

내보내기 UI에서는 선택 행, 현재 검색 결과, 전체 범위의 차이를 명시해야 한다.
내보내기는 현재 미구현이며 파일 형식/범위는 아직 확정되지 않았다.

### S08 변경 감지

기관/소스/후보 유형/검토 상태별 목록과 이전 값·새 관찰 값의 비교 화면을 제안한다.
Source의 coverage와 비교 범위를 표시한다.
UNKNOWN/ADDITIVE_ONLY에서는 누락을 삭제 근거로 만들지 않는 기존 의미를 보존한다.
COMPLETE_SNAPSHOT의 누락 후보도 자동 비활성화/삭제 명령이 아니다.
승인 동작은 검토 대기의 동일한 처리 경로로 연결하며 별도 승인 writer를 만들지 않는다.

### S09 검토 대기

현재의 단순 pending 집계를 실제 검토 화면으로 확장해야 하는 신규 영역.
후보 목록 → 기관/부서/업무 문맥과 출처 → 반영 미리보기 → 명시적 결정 흐름을 제안한다.
수집 오류 정리와 Master 반영 승인처럼 결과가 다른 작업은 유형/필터로 구분한다.
승인/반영, 거절, 보류의 의미와 권한/이력 정책을 확정한 뒤 구현한다.

이미 처리된 후보, 최신 데이터가 바뀐 후보, 중복 클릭, 반영 실패 상태를 설계한다.
사람/재직 관련 후보는 기존 apply가 0건 생성하는 미완성 영역임을 명시한다.
검토 화면이 있다는 이유로 자동 반영을 기본값으로 삼지 않는다.

### S10 통계/리포트

기존 대시보드 집계를 자세히 조회하는 화면을 제안한다.
기관/수집 방법/연락처 유형/기간별 실제 저장 데이터의 범위를 먼저 확정한다.
새로운 예측·AI 분석·임의 점수는 이 이미지로 승인되지 않았다.
필터 없는 전체 수치와 선택 범위 수치를 혼용하지 않는다.
리포트의 파일 형식·컬럼·기간 범위는 별도 결정한다.

### S11 설정

이미지에는 메뉴만 있고 실제 설정 화면의 구현 근거는 없다.
현재 설정 코드와 사용자 운용 요구에 근거한 항목만 최종 범위에 넣는다.
제안 검토 항목: 데이터/증거 경로, 기본 수집 제한, 실제 구현할 수집 정책.
기관/부서별 소스 정책과 앱 전역 기본값을 구분한다.
백업·복원·스케줄러·인증·계정·테마 전환을 임의로 추가하지 않는다.
저장, 변경 취소, 유효성 오류, 저장 실패 상태는 실제 저장 계약과 함께 설계한다.

## 5. 공통 상태

화면마다 해당 상태를 명세하고 가짜 성공 데이터를 넣지 않는다.
- 초기 빈 상태 / 필터 결과 없음 / 미선택.
- 로딩 / 진행 중 / 완료.
- 유효성 오류 / 중복·충돌 / 저장 오류.
- 조회 실패 / 부분 결과 / 지원하지 않는 동작.
- 이미 처리됨 / 사용자 취소 / 변경사항 미저장.

로딩 실패를 0건으로 바꾸지 않는다.
미지원 버튼을 활성화한 채 눌러도 아무 일도 일어나지 않게 만들지 않는다.
동일 항목의 상태와 집계는 같은 기준으로 표시한다.

## 6. UI Freeze 체크 기준

전체 화면의 역할, 주요 열, 필터, 행 선택, 상세 열기/닫기, 화면 이동을 확정한다.
모든 주요 버튼의 입력·결과·오류·비활성 조건을 확정한다.
Excel 중복 처리, 자료없음 판정, 수집 단계, 검토/반영, 삭제 영향, 내보내기 범위를 확정한다.
최소 창 크기와 긴 텍스트/많은 행의 스크롤 규칙을 확정한다.
최종 기능 범위와 미지원 표시를 함께 승인한다.

현재 체크 결과: 미완료. 대시보드 이미지 한 장으로 전체 Freeze 처리하지 않는다.
